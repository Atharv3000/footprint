# Pip guided tutorial

The existing Pip card, transparent character cutout, colors, reverse spotlight, blinking read hint and pulsing action cue are retained. Twenty steps cover Fitness Log tools/workout days, calorie totals/meals/pet care, Community challenges, map controls and Activity/Progress/Insights/Badges in Account.

Each step runs read -> act -> waiting -> read/done. Read taps advance exactly one dialogue bubble. Only the measured highlighted region accepts an action. Navigation and subtab targets invoke the original control callback. Section targets acknowledge their explanation; they do not open permission prompts, record an activity, submit logs or create challenges. Actual route readiness confirms the action before advancing. Failed navigation returns to act after five seconds.

New account eligibility is persisted by AuthProvider before the signed-in user becomes visible. This includes email signup and first-time federated accounts, even when another account has already used the phone. Profile setup completes first, then the Tabs tutorial provider automatically loads the pending account tour. Existing accounts stay undisturbed. Completion and resumable progress are stored separately per normalized account ID at @footprint_tutorial_account_v2_<id>. Re-enrollment never resets progress. The old install marker is retained only for migration; unfinished old three-step tours restart with the expanded sequence, completed old tours stay completed.

TutorialAnchor retains the original View and layout for explanatory sections. TutorialButton retains TouchableOpacity behavior for real subtabs. TutorialScrollView and TutorialScrollScope automatically reveal targets inside ScrollView and FlatList. Hidden pet content is restored for a resumed pet-care step; route restoration opens the correct page. On compact screens an explanatory section's spotlight can crop to its visible top to leave room for the dialogue. The card avoids covering the action region. Reduced-motion and accessibility behavior remain supported.

The underlying app is inaccessible to touch/accessibility while active and Android Back is consumed. A full input shield covers even the cutout during read. Account -> three-dot menu -> Preview tutorial replays the tour with Close preview and never changes real saved progress/completion. It navigates real tabs but does not reset account data.
